# Claim Boundaries

This repository intentionally uses a strict evidence vocabulary.

## IMPLEMENTED
A code path or persistent component exists.

## OBSERVED
Runtime evidence shows a component executed in a recorded environment.

## MEASURED
A defined experiment produced a reproducible/described metric.

## NULL
A properly executed test failed to support the proposed advantage.

## HYPOTHESIS
A falsifiable research proposition that remains unresolved.

## METAPHOR / MODEL
A conceptual design lens such as synapse, organism, cosmic, or heartbeat. It is not automatically literal biology or physics.

## Explicit non-claims

This software does not establish machine consciousness, a biological nervous system, literal higher-dimensional physical cognition, that quantum randomness improves language-model accuracy, that persistent state equals subjective experience, or that an FFT of an embedding creates a new physical information frequency.

Those may be research questions in the wider CST lineage, but software labels are not experimental proof.

## Why preserve null results

A research architecture becomes stronger when failed mechanisms are documented. The CST/COSMOS lineage includes examples where a mathematically live-looking state mechanism silently collapsed because of normalization, saturation, clamping, or kernel bandwidth. Those failures are design knowledge.
